# وضعیت پروژه و گزارش نهایی — Network Commander

آخرین به‌روزرسانی: ۲۰۲۶-۱۱-۲۰ · نسخهٔ ۰٫۱٫۰

## ۱. انجام‌شده و با تست خودکار بررسی‌شده (روی شبیه‌ساز)
بک‌اند ۷۰ تست پایتون، فرانت‌اند ۳ تست کامپوننت (vitest)، ساخت فرانت‌اند موفق، و یک اجرای مرورگری (Playwright) شامل ورود، شناسایی، فرم VLAN، پیش‌نمایش، اعمال و راستی‌آزمایی بدون خطای کنسول.

- موجودی دستگاه، CSV، اسکن CIDR (TCP/بنر)، فیلتر/گروه، اعتبارنامه‌های رمزنگاری‌شده، پین کلید SSH (منطق).
- شناسایی (Cisco IOS/IOS XE/NX-OS، MikroTik v6/v7، FortiOS) و تشخیص قابلیت با probe؛ رد خروجی فروشندهٔ نادرست.
- موتور پیکربندی: Hostname، VLAN (۳ نوع)، Interface، Static route، NTP، DNS، Syslog، SNMP v2c، Save/Reboot؛ پیش‌نمایش، پشتیبان پیش از تغییر، verify، skip وقتی از قبل برقرار است، رول‌بک اشیای جدید، `unknown_state` در قطع اتصال، قفل per-device، ریسک (low→critical) و تأیید.
- پشتیبان رمزنگاری‌شده، diff، پیش‌نمایش بازگردانی.
- چنددستگاهی (ترتیبی/موازی/توقف/لغو/ناسازگاری/ممنوعیت critical)، قالب‌ها با نسخه.
- پایش (up/CPU/mem، آستانه، رویداد)، توپولوژی از همسایه‌های جمع‌آوری‌شده، عیب‌یابی.
- امنیت: نشست/CSRF/Host/Origin، ماسک اسرار، ممیزی، مهاجرت‌های Alembic (بالا/پایین، حفظ داده).

## ۲. نوشته‌شده ولی آزموده‌نشده
- **هر اتصال SSH واقعی** (Netmiko) و **هر دستگاه واقعی**. فرمت خروجی‌های سیسکو/میکروتیک/فورتی را از دانش خودم در شبیه‌ساز بازسازی کرده‌ام؛ ممکن است با فریمور واقعی نخواند (verify شکست می‌خورد، نه تغییر نادرست بی‌صدا).
- DPAPI، پین کلید میزبان روی سرور SSH واقعی، ورود با کلید خصوصی.
- بسته‌بندی PyInstaller، نصب‌کنندهٔ Inno Setup، اجرای خودکار با ویندوز، `--stop`، اسکریپت پشتیبان داده: workflow ساخته شده ولی هنوز اجرا نشده.
- پایش زمان‌بندی‌شدهٔ پس‌زمینه (Scheduler) فقط به‌صورت poll دستی در تست‌ها آزموده شده.
- job انتشار ریلیز (تگ `v*` ← pre-release با نصب‌کننده و sha256) نوشته شده ولی اجرا نشده؛ Actions در حساب مالک تا این لحظه شکست می‌خورد (بدون runner).
- نقطهٔ انتهایی خاموش‌کردن سرویس (`/system/shutdown`) تست خودکار ندارد.

## ۳. پیاده‌نشده (و دلیل)
| مورد | دلیل/وضعیت |
|---|---|
| OSPF/OSPFv3/EIGRP/BGP/RIP، VRF، PBR، route-map، prefix-list | زمان؛ نیازمند مدل و آزمون جدا برای هر پروتکل |
| ACL، NAT، سیاست/آبجکت/زون فایروال، AAA، 802.1X، DHCP snooping/DAI | همان؛ مدل امنیتی هر فروشنده متفاوت است و باید بومی ساخته شود |
| DHCP، QoS، STP/MSTP، LACP، port-security، storm control، SPAN | پیاده نشده |
| IPv6، SNMPv3، SNMP polling، شمارنده‌ها/آمار ترافیک واسط، دمای سخت‌افزار | پیاده نشده |
| بی‌سیم، SD-WAN، VPN (IPsec/WireGuard/SSL)، HA، کاربران سیستم | پیاده نشده |
| REST API فورتی‌گیت، RouterOS API، NETCONF/RESTCONF | فقط SSH CLI استفاده شده |
| رول‌بک زمان‌دار (confirm/`configure replace`)، اعمال کامل بازگردانی | عمداً/هنوز نه؛ بدون قول رول‌بک غیرقابل‌تضمین |
| حذف مسیر ایستا و حذف NTP/DNS روی FortiGate، Bridge VLAN filtering میکروتیک | با پیام `unsupported` رد می‌شود |
| دسترسی LAN با TLS و ورود کاربر | پیاده نشده؛ فقط localhost |
| ویرایش دستی توپولوژی در UI | API لینک دستی هست؛ UI ندارد |
| افزونهٔ فروشنده با کشف خودکار | فقط `register()` برنامه‌نویسی |
| اجرای مستقیم قالب از صفحهٔ قالب‌ها | پیش‌نمایش هست؛ اعمال از «Multi-device change» |
| ترجمه/محلی‌سازی فارسی UI | UI انگلیسی است |

## ۷. محدودیت‌های شناخته‌شده
- شبیه‌ساز برداشت من از CLI است، نه مرجع رسمی.
- وقتی دو خط ورودی یک شیء را تغییر می‌دهند و فقط یکی شکست بخورد، رول‌بک فقط برای اشیای جدید ممکن است؛ برای تغییر شیء موجود پشتیبان پیش از تغییر ملاک است.
